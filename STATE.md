## Astryx beta-feedback exhibits
<!-- Case-study material: real, source-confirmed gaps/quirks found working against Astryx 0.1.4 as a beta design system. Not action items for this project — a running record for eventual feedback to the Astryx team. -->
1. No stat/metric primitive — Phase 3 (2026-07-10). `metric` node built custom (Text composition) after confirming via `astryx search` that no Stat/Metric component exists in the library.
2. `vega` package not published to npm — documented in CLAUDE.md §5 from project inception; this is why `recharts` is on the closed dependency list for charts instead of Astryx's own intended chart primitive.
3. `Table` edge-bleed fires per-instance in multi-child containers — Phase 4 (2026-07-10). `Table`'s "bleed to card edge" feature (negative margin keyed to a Card-inherited CSS custom property, `--container-padding-block-{start,end}`) applies independently to every table sharing one padded container regardless of nesting depth, silently canceling any author-added gap between them. The override point exists (resetting the custom property works cleanly) but is non-obvious — undocumented in Table's own component docs, only found by reading source.
4. `AspectRatio` has no built-in width cap — Phase 7 (2026-07-10). Inside a full-width scene-grid column, `AspectRatio(ratio=1)` stretched to a 1248×1248px square with no way to bound it via documented props; the caller must supply an external max-width wrapper. Not documented as a caveat in the component's own docs — a size-unconstrained parent is a normal layout context, not an edge case.
5. `ClickableCard`'s accessible `role="button"` element sits *behind* the visible card surface in stacking order — Phase 8B WO-2 (2026-07-10). Confirmed via a genuine Playwright pointer-interception error (`getByRole('button', {name}).click()` timed out, reporting the visible card div "intercepts pointer events"), not guessed: a real mouse click lands on the card's own surface/handler, while the ARIA button exists purely for keyboard/screen-reader activation and is never the real pointer target. Not documented as a caveat in the component's own docs. An accessibility-relevant layering finding — a screen-reader user tabbing to the button and a mouse user clicking the card are hitting two different elements, which is presumably intentional (matches "Nested interactive elements work independently" in the component's own anatomy notes) but is non-obvious enough to be worth flagging upstream.
6. No semantic "add/plus/new" `IconName` exists — Phase 8C (2026-07-11). The closed `IconName` list (`astryx component Icon --dense`: close, chevronDown, chevronLeft, chevronRight, check, success, error, warning, info, calendar, clock, externalLink, menu, moreHorizontal, search, arrowUp, arrowDown, arrowsUpDown, funnel, eyeSlash, viewColumns, copy, checkDouble, wrench, stop, microphone) has nothing for "create new" — a common enough action (Sidebar's "New investigation" item) that its absence is worth flagging upstream. Resolved by omitting the icon entirely (`SideNavItem.icon` is optional) rather than forcing a semantically wrong substitute.
7. No semantic "watch/bookmark/star" `IconName` exists — Phase 8G WO-2 (2026-07-12). Same closed list as exhibit 6 above has nothing for "track/follow this" either — no eye, star, or bookmark glyph. `eyeSlash` exists but means "hidden," the opposite of watched, so using it would be actively misleading, not just imprecise. Resolved with `checkDouble` (weak fit: reads as "confirmed/done," not "watched") for both the Watchlist rail icon and the EntityHeader/Entities-pane Watch action, logged here rather than silently accepted as the right icon.
