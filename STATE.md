- 2026-07-12: mcp-server's `StreamableHTTPServerTransport` accepts only one client session per server process lifetime — a second `Client.connect()` against an already-used, still-running server instance fails with "Server already initialized" rather than opening a new session. - 2026-07-12: Playwright's own `webServer` (`reuseExistingServer: true`, `fullyParallel: true`) races Storybook/Vite's per-story, compile-on-first-request model — reproduced three times same day, understanding refined each time rather than re-guessed. First diagnosis (dependency pre-bundling not finished before the HTTP health check passes) was real but incomplete: a fourth occurrence hit the identical 8 stories against a server that had already been running and serving other pages for over a minute — ruling out "server not warm yet" as the sole cause. Refined root cause: Vite compiles each story's own module graph on its FIRST request, lazily, independent of overall server uptime — a story nobody has loaded yet is still "cold" no matter how long the server process has been alive, and several parallel workers hitting that same never-before-compiled route simultaneously all stall past the 30s timeout together. A second full run immediately after (now with those exact stories compiled from the first run's own attempt) passed clean with no other change. Fix, revised: pre-warming must visit the SPECIFIC stories about to be tested (or accept that a just-restarted Storybook's first `test:visual` run may need one throwaway retry) — warming one unrelated story (e.g. `shell-frame--default`) does not warm others. Candidate rule: treat a `test:visual` run immediately following any Storybook restart as unreliable by default; either pre-warm every story class in the suite or budget for exactly one retry, and don't read a first-run failure confined to never-before-visited stories as a real regression without re-running first.
